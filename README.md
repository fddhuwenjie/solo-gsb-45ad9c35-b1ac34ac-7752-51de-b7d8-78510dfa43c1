# 展陈分支导览（Exhibit Branch Guide）

本地展览使用的**分支式讲解导览** Web 应用：编辑者编排讲解节点与选项，选项把访客带到下一节点；访客在岔路自行选择参观路线。

技术栈：Python · Flask · SQLite · 原生 JavaScript（无前端构建）· Docker / Docker Compose。

## 一条命令启动

```bash
docker compose up -d --build
```

启动后访问：

| 页面 | 地址 |
| --- | --- |
| 访客入口 | <http://localhost:5000/> |
| 编辑后台 | <http://localhost:5000/editor> |

端口为 **5000**（在 `docker-compose.yml` 的 `ports` 中修改宿主机端口）。
数据通过命名卷 `guide-data` 持久化到容器内 `/data/guide.db`，容器重建不丢数据；首次启动自动建库建表。

停止：`docker compose down`（数据保留）；连同数据一并清除：`docker compose down -v`。

## 不使用 Docker（本地直跑）

```bash
pip install -r requirements.txt
DB_PATH=./data/guide.db python app.py
```

然后访问 <http://localhost:5000/>。

## 使用说明

### 编辑（`/editor`）

1. 「＋ 新建节点」创建讲解节点，填写标题与讲解正文。
2. 在节点详情里「添加选项」，填写选项文案并选择**指向的下一节点**；可用 ↑/↓ 调整选项顺序（访客端按此顺序展示）。
3. **末页节点不添加任何选项**，访客到达后显示「导览结束」。
4. 用「设为入口」指定访客的起点。
5. 「保存草稿」随时保存；草稿与公开版本互相独立。
6. 「发布新版」前系统自动校验，校验失败会逐条列出**节点与原因**，此时草稿和上一公开版本都保留原样。

发布校验规则：

- 必须存在入口节点；
- 从入口出发，**每个节点都必须可达**（孤立节点报错）；
- 每个选项的**目标节点必须存在**；
- 选项构成的有向图**不能有环**（否则访客可能无法走到末页）。

### 参观（`/`）

- 打开展览首页点击「开始参观」，系统基于**当前公开版本**新建一次访问并跳转到该访问的专属链接（`/v/<token>`）。
- 访客只能看到并选择**当前节点的选项**；没有选项即为末页。
- 专属链接保存了所用版本与**已选路径**：刷新页面、关闭后重开、或换设备打开都能从当前节点继续，页面上方以面包屑展示已走路线。
- 每个版本发布后即为不可变快照。编辑者修改草稿或发布新版：
  - **进行中的访问仍沿旧版前进**（创建时固定版本）；
  - **之后新开始的访问才读取最新公开版**。
- 尚未发布任何版本时，访客页提示「暂无导览」。

## API 概览

| 方法 & 路径 | 说明 |
| --- | --- |
| `GET /api/draft` | 读取草稿与当前公开版本号 |
| `PUT /api/draft` | 保存草稿（整存整取） |
| `POST /api/publish` | 校验并发布新版本；失败返回节点级错误（422） |
| `GET /api/published` | 查询当前公开版本信息 |
| `POST /api/visits` | 基于当前公开版创建访问（固定版本） |
| `GET /api/visits/<token>` | 取回访问：版本、已选路径、当前节点 |
| `POST /api/visits/<token>/choose` | 在当前节点选项中做一次选择并前进 |

## 数据模型（SQLite）

- `draft_meta` / `draft_nodes` / `draft_options`：编辑草稿（节点、有序选项、入口）。
- `versions`：每次发布写入一行不可变 JSON 快照（`id` 即版本号 v1、v2…）。
- `visits`：每次参观一行，记录 `version_id`（版本固定）、`current_node_id` 与路径 JSON。

数据库开启 WAL 模式以支持多 worker 并发。
